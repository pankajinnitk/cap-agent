# Deploy Pro Code Agent and Joule Capabilities

In this exercise, you build the MTA archive, deploy the agent to SAP BTP, Cloud Foundry environment Joule capabilities and verify it is working correctly using curl commands against the deployed agent.

## Prerequisites

You have successfully logged in to the SAP BTP Cloud Foundry environment, targeted the specific organization and space where the agent will be deployed, and authenticated with Joule to deploy the custom capabilities.

- [Login to Cloud foundry](./1.1-Develop-Agent-And-Joule-Capabilities.md#prerequisites)
- [Login to joule](../ex0/Setup-Joule-Workzone.md#login-to-joule-cli)

## Deploy the Agent using Plugin

Give Claude Code the following prompt. Claude in turn loads the joule-a2a-agent skill (deploy-agent) and starts building the agent.

> [!IMPORTANT]
> Verify that you are targeting the correct Cloud Foundry organization and space using `cf target`, and ensure the appropriate Joule instance is selected using `joule status` to prevent configuration issues.

```text
Deploy the agents with Joule capabilities.
```

**What happens in the background:**

1. **Detect project type** — the plugin reads the `mta.yaml` and `package.json` files to confirm this is a CAP-based A2A agent, then checks the Joule tenant's A2A protocol version to ensure schema compatibility.
2. **Build the MTA archive** — runs `mbt build` to compile the TypeScript source and package the app with its service bindings into a deployable `.mtar` archive.
3. **Deploy to Cloud Foundry** — runs `cf deploy` with the `.mtar` archive. CF provisions the destination service instance, binds it to the app, and starts the `psm-joule-agent-srv` process.
4. **Verify the agent card** — once the app is running, it polls `/.well-known/agent.json` on the live URL to confirm the agent is reachable and responding correctly.
5. **Create the Joule destination** — creates the `PSM_JOULE_AGENT_A2A` HTTP destination in the Joule subaccount pointing to the deployed agent URL.
6. **Deploy Joule capabilities** — runs `joule deploy` with the capability YAML files so Joule can route user intents to the agent.

> [!IMPORTANT]
> The plugin handles the full deployment loop autonomously. If any step fails (build error, CF staging failure, agent card returning 404, destination misconfiguration), it diagnoses the root cause, applies the necessary code or configuration fix, and retries the failed step. You don't need to manually inspect logs or re-run commands. The plugin iterates until the deployment succeeds end to end.

**Verify that the application is running:**

```bash
cf apps

# Copy the route of psm-joule-agent-srv as <AGENT-SERVICE-URL>
```

If you want to check logs, run the following:

```bash
# Most recent logs
cf logs psm-joule-agent-srv --recent

# Live tail (useful during a test)
cf logs psm-joule-agent-srv
```

Key log lines to look for are listed below:

| Log line                                          | Meaning                                                    |
|---------------------------------------------------|------------------------------------------------------------|
| `[MCP] Fetching destination 'PSM_CAP_APP'...`     | Agent is calling SAP BTP Destination Service for a fresh token |
| `[MCP] Got Bearer token from destination service` | Token fetched successfully                                 |
| `[MCP] Loaded N tools from PSM MCP server`        | MCP connection established                                 |
| `[TOOL] query: {...}`                             | MCP tool was called and returned data                      |
| `Task <id> completed`                             | Agent finished successfully                                |

## Test and Troubleshoot the Deployed Agent

To test the deployed agent, you must first create a destination in the subaccount. This destination serves as the connection point to the Poetry Slam Manager application using the MCP.

1. Get the information from the service key of the service broker instance named *psm-sb-sub1-full*.
    1. Go to **BTP Cockpit → HOW-PA Consumer nnn Subaccount → Services → Instances & Subscriptions**.
    2. View the credentials of the service broker instance named `psm-sb-sub1-full`.
    3. For the `ServiceBrokerEndpoint`, get the URL of psm-servicebroker in the endpoints section.
    4. Get the `ServiceBrokerClientID` and `ServiceBrokerClientSecret` from the uaa section.
    5. For the `ServiceBrokerTokenServiceURL`, get the URL of the uaa section and add /oauth/token.

2. Go to **BTP Cockpit → HOW-PA Joule Agent nnn Subaccount → Connectivity → Destinations**.

3. Create a new destination with the following field values:

   | Parameter Name              | Value                                                          |
   | :-------------------------- | :--------------------------------------------------------------|
   | **Name**                    | `PSM_CAP_APP`                                                  |
   | **Type**                    | `HTTP`                                                         |
   | **Description**             | Destination description. For example, `Poetry Slams Manager`.  |
   | **URL**                     | `ServiceBrokerEndpoint`                                        |
   | **Proxy Type**              | `Internet`                                                     |
   | **Authentication**          | `OAuth2ClientCredentials`                                      |
   | **Client Id**               | `ServiceBrokerClientID`                                        |
   | **Client secret**           | `ServiceBrokerClientSecret`                                    |
   | **Token Service URL**       | `ServiceBrokerTokenServiceURL`                                 |
   | **Token Service URL Type**  | `Dedicated`                                                    |

> If any application functionality fails during testing, use Claude Code to diagnose the issue and trigger an automated redeployment.
